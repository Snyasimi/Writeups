## Microprocessors and how the operating system uses it

The computer is made up of several basic elements
- Memory
	Memory stores data and programs
- Processor
	This controls the operation of the computer and data processing functions, if there's only once processor it is refered to as a central processing unit.
- I/O modules
	These modules move data between the computer and it's external environment; these include Disk, terminals and communication equipment
- System bus
	Provides communication among processors, main memory and I/O modules


## The Micro processor
Ah, yes these have helped the evolution of computers. A microprocessor which has a single processor on a single chip. Before, the micro processor was slow than multichip processors, but micro processors have evolved in moving information; this is typically done in sub-nanoseconds, thats fast.

Microprocessors these days have improved and contain multiple processors in a single chip. Each chip is called a *socket* and can contain multiple processors called *cores*, each with multiple levels of memory caches. A laptop can have 2 or 4 cores each with 2 hardware threads, this makes a total of 4-8 logical processors.

But a computer can have more microprocessors, each one specializing in a different task, for instance, you can have a GPU -- for numerial computation of arrays, render graphics etc, you can have DSPs for Digital Signal processing for processing audio or video, CODECS for encoding/decoding information or providing encryption and security.

But due to improvements in tech and needed support for handhelp devices like your phone, classical microprocessors are giving way to *SoC* System on chip, where these functionalities handled by different microprocessors(GPU,DSPs,I/O) and caches are put on one single chip.

## Instructions

The processor executes instructions which are stored in memory, the CPU does this in 2 steps; the **fetch**, retrieveing instructions from memory, one at a time and **execution**. To execute a program, these steps are repeated until termination of the program, when the processor is turned off, when there's an interupt or when an unrecoverable error occurs. This process is known as the *instruction cycle*

- fetch stage 
- execute stage

The processor fetches instructions from main memory in a sequential manner. To keep track of the next instruction, the processor will use a memory slot inside it called a *program counter (PC)*. After fetching the instruction, it is then loaded into a special register known as the *instruction register*, the instruction contain bits that specify the action the processor is to take. The program counter is updated to point to the location of the next instruction; the PC moves in a sequential manner, that is it fetches instructions in a linear and sequential manner, but this might not always be the case as some instructions may make the processor fetch the next instruction from a different memory location.

These instructions fall into the followinf categories.
- Processor - Memory
	Data may be transfered from the processor to main memory or from memory to the processor
- Processor - I/O 
	Data may be transfered from the processor to or from a peripheral device by transfering btwn processor and I/O module
- Data processing 
	The processor may perform some arithmetic or logical operations on data.
- Control 
	An instruction may soecify that the sequence of execution be altered; the processor might fetch an instruction from location 149 , whichspecifies the next instruction will be from the location 182, thus the processor will set the program counter to 182, thus on the next fetch stage, instruction will be loaded from 182 instead of 150.

An instructions execution may involve a combination of these actions.

The processor also contains a register called the *Accumulator(AC)* which stores results of processing.

## Interrupt processing

An interrupt is anything that changes the sequence of operations on a processor. Interupts disrupt the normal execution of a program in order to service something of higher priority or to process other data as the processor is waiting for an I/O operation to be done.

Interrupts are important because they make efficient use of the processor. Most I/O devices are slow compared to the processor; million times slower. There are multiple forms of interupts, these include;

- Program interrupt
	These are generated by running programs, this can be a result of instruction execution eg attempting to execute illegal machine instruction or trying to reference outside a user's allowed memory space.
- Timer
	These are generated by a timer within the processor. This allows the OS to perform certain function on a regular basis.
- I/O 
	These are genrated by an I/O controller, to signal completion of an operation or to signal error conditions
- Hardware Failure
	Generated by a failure, such as poer failure or memory error.


### Interrupts and the instruction cycle

During an I/O operation, the processor doesn't need to keep waiting for the I/O operation to be done in order to continue executing a user program. Instead the processor does something else while the I/O operation is being done, this can be reading data from computer memory to the I/O device. Once the external device becomes ready to accept data from the processor, the I/O module for that external device sends an interrupt request signal to the processor. The processor responds by suspending the current program branching off to a routine to service the I/O device,known as *an interrupt handler*

The processor and the OS are responsible for suspending and resuming the user program. Interrupts are accomodated by adding one more stage in the *instruction cycle*, this stage is known as the **interrupt stage**. During the instruction cycle, in the interupt stage, which is after the execute instruction stage, The processor will check to see if there is any interrupt pending, indicated by the presence of an interrupt signal. If no interrupts are pending,the processor proceeds to the fetch stage and normal execution resumes. If there's an interrupt, the processor suspends the execution of the current program and executes an *interrupt handler routine*. This routine is part of the OS, it detemines the nature of the interrupt and performs whatever actions that are needed. Once the routine is complete, the OS can resume normal execution of the user program at the point of interruption. Extra instructions are executed to determine the nature of the interrupt and to decide on the appropriate action.

### Interrupt processing

When an I/O device completes an I/O operation, the followinf sequence of events occur

1. The device issues an interrupt signal to the processor.
1. The processor finishes executing the current instruction before responding.
1. The processor tests for a pending interrupt request, determines there's one and sends an acknowledgement signal to the device that issued the interrupt. The acknowledgement allows the device to remove the interrupt signal.
1. The processor prepares to transfer control to the interrupt routine, it saves the information of the current program so that it can resume executing it once the interrupt is serviced, minimum information is required, the *program status word(PSW)* and the location of the next instruction. once this information is pushed in the control stack, the CPU transfers control to the interrupt routine.
1. The processor loads the program counter with the entry location of the interrupt handling routine that will respond to this interrupt. Depemding on the computer architecture there might be a single program for each type of interrupt or one for each device and each type of interrupt. If there is more than one type of interrupt-handling routine, the processor might determine which to invoke, this information might also be included in the original interrupt signal, or the processor might have to issue a request to the device that issued the interrupt to get a response that contains the needed information.
1. Once the interrupted program's PC and PSW are saved to the control stack, the processor registers The stack pointer is updated to point to the new top of stack, and the program counter is updated to point to the beginning of the interrupt service routine.
1. The interrpt handler proceeds to process the interrupt.
1. Once the interrupt processing is complete, the saved register values are retrieved from the stack and restored to the registers.
1. Finally the PSW and program counter are restored, as a result, the next instruction to be executed wil be from the previusly interrupted program  

### Multiple Interrupts

To process multiple interrupts, two options can be taken
1. Disable interrupts while an interrupt is being processed, the processor will ignore all interrupt signals until it's done processing the current one. once done, the processor will re-enable interrupts. In this fasion, interrupts are handled in a strict sequential order.

The downside is, it doesn't consider the priority of the various interrupts or the time critical needs.

1. The other option is to define priorities for interrupts to allow low-priority interrupts to be interrrupted by higher priority interupt handlers

## Memory Hierarchy

Memory is a crucial resource, and should be utilized well. Memory comes with three constraints. How fast? how much? and how expensive?  

There are some conditions you have to consider when designing memory, these include;
- Faster access time, greater cost per bit.
- Greater capacity, smaller cost per bit.
- Greater capacity, slower access speed.

To take advantage of all 3 pros, designers have come up with a *memory hierarcy*. In this hierarchy, memory is organised in such a way that the smaller, faster and expesive memory is supplemented by larger cheaper memory. As you go down the hierarcy you find that you are decreasing the cost per bit, increasing the capacity and decreasing frequency of access to the memory by the processor.

#### Terms to remember

- Hit ratio: The rate of success of memory requests that have been serviced by the smaller, faster memory layer. e.g the cache without needing lookup from slower memory.

- Locality of reference: The principle of locality, if particular information is fetched from a certain memory region, there's a possibility that that whole *'cluster'* might be used again by the processor. locality if reference uses the same concept.

- Memory cycle time: The time it takes to write/read one word to/from memory.
### Cache Memory

Funny enough, this memory is invidisible to the OS and interacts with memory management hardware.

The processor executes instructions as fast as the memory cycle time allows it, this means the processor can be fast but the memory cannot keep up; processor speeds increase rapidly than memory access speeds. Why can't we build memory that matches the processor's registers? well it's expensive. A better solution is to use the principle of locality and provide small, fast memory between the processor and the main memory, the *cache*.

You can have multiple levels of the cache ie L1, L2, L3 caches. 

Main memory consists of fixed size blocks containing K words each. When the processor attempts to read a byte or word from memory, the cache is checked first, if it contains the word, the word is passed to the processor. If not, a block of main memory consisting of a fixed number of bytes is read from main memory and placed in the cache, then the word is passed to the processor.

A cache consists of slots or lines of k words each, the number of slots is less than the number of main memory blocks. If a word is not found in the cache and read from the a main memory block, the entire block is moved to one of the slots in the cache. Since these slots are shared, each slot contains a tag that identifies which block is currently being stored.

> The tag is usually some number of higher-order bits of the address and refers to all
> addresses that begin with that sequence of bits. eg 2-bit flag(01) 0f 6 bits: 011011, 010110, 011010,010111. 

**Block size** is the unit of data exchanged between the cache and main memory. As the block size increases, so does the hit ratio, due to the principle of locality. A *mapping function* determines which location a block will occupy, a *replacement algorithm* chooses which block to replace. A block that is least lickely to be used in the near future is the preferred candidate. But since predicting that is quite difficult, a policy known as *least-recently-used(LRU) algorithm* is used. The strategy is to replace blocks that have been in the cache the longest and have not been referenced.

If contents in a block are altered, these changes need to be written to main memory before replacing it. The *write policy* dictates when the memory write operation takes place, it can be either;

- Writes occur when the block is altered.
- Writes occur when the block is replaced.

One reduces memory write operations, the other one leaves data in main memory at an obsolete state.

### Direct Memory Access (DMA)

Before, there were various ways the processor to perform I/O operations.
1. Programmed I/O in this mode, the I/O module performs the requested action and sets appropriate bits once done, it does not interruot the processor, rather , the processor needs to keep checking the status of the operation, this degrades the perfomance of the system.
1. Interrupt driven I/O: In this mode, the processor issued the I/O command and goes to do something else, the I/O module will interrupt the processor once it's ready to exchange data. The processor executed the data transfer, then resumes processing. This is better than programmed I/O, the only issue is, it interrupts the processor.

DMA solves the short coming. A DMA module can be a separate module on the system or the I/O module's. When the processor needs to read/write a block of data, it delegates to the module and giving it information it needs to handle the operation.
Tis information include;

- Whether it's a read or write.
- Addr of the I/O module involved.
- Starting memory location to read data from or write data to.
- THe number of words to be read or written

The DMA module transfers an entire block, word by word, once it's done, it interrupts the processor(only involved at the begining and end). 

The DMA module makes use of the system bus to transfer data, this means the processor can and will sometimes wait the module to complete it's operations, this is better than handling interrupts. It slows down the processor.
